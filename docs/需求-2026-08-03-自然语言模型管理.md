## 1. 背景与现状

- 本机已配置 `[model_routing] enabled=true model_pool=["deepseek-v4-flash","grok-4.5"]`（`~/.grok/config.toml`，普通 turn 路由，重启生效）。
- 现状换模型只有 `/model` 命令；且 `/model` pin 会禁用普通 turn 路由（设计如此，见交接词 §7 坑）。
- 现有约束：401 不触发换路（认证失败 ≠ provider 不可用）；provider 失败才走 `/model` 指引（`nextgen_control.rs::failure_escalation_guidance`）。

## 2. 需求

### R1 默认模型
- lumen2 协作默认模型 = **deepseek-v4-flash**。
- 单模型干活（默认路径）时 Builder/Executor 默认用 flash。

### R2 自然语言换模型（带确认）
- 用户直接说"换成 XX / 用那个便宜的 / 换 grok"等自然语言即可表达换模型意图，无需 `/model` 命令。
- 系统从**模型池**（deepseek-v4-flash、deepseek-v4-pro、grok-4.5、kimi-k3、deepseek-chat 等可用项）**分析用户指哪个**，然后**弹出确认**（"你指的是 X 吗？"），用户确认后才生效。
- 分析歧义或池外模型时，确认框必须给出候选；不得静默猜测。

### R3 多模型分工
- 用户说"两个/三个模型分工"：按用户描述把任务拆成多个子任务，每个子任务交给指定模型独立执行（并行）。
- 分工声明必须包含：模型 → 子任务映射、汇合点、各子任务边界（禁止交叉改同一文件导致冲突）。

### R4 多模型协作（非分工）
- 用户说"一起做同一个"：多个模型**并行做同一任务**，产出各自方案/实现，再由 Director 汇总、对比、合并或让用户选。
- 与 R3 的区别：R3 是拆任务、R4 是同任务多视角/多实现。

## 3. 与现有机制的协调（实现时必须遵守）

1. **/model pin 语义不可破坏**：自然语言换模型与 `/model` pin 的关系需明确定义（建议：自然语言换模型 = 普通 turn 路由池内选择；显式 pin 仍优先且禁用普通路由——待设计确认）。
2. **401 不换路**：认证失败不得触发自动换模型（沿用现有 `auth_error_no_retry` 语义）。
3. **fail-closed**：分析不出用户指哪个模型时，默认回到 deepseek-v4-flash 并说明，禁止乱换。
4. **SOURCE_LOCK 与 docs**：本文档是 docs-only 变更，不刷新 SOURCE_LOCK（保持 binary tuple）。
